## **系统概述**

剧情演出系统（Plot Performance Platform）是一个基于**行为序列化**的通用剧情演出框架。它将剧情演出抽象为"指令序列"的执行过程，通过 JSON 序列化实现剧情脚本的数据化存储，并通过反射机制实现指令的动态加载与执行。

### **核心设计理念**

1. **数据驱动**：剧情内容完全由 JSON 数据驱动，策划无需编写代码
2. **指令化设计**：所有剧情行为抽象为可序列化的指令对象
3. **帧序列执行**：指令按帧组织，支持同帧多指令并行执行
4. **资源预分配**：采用静态预分配策略，避免运行时频繁实例化
5. **高度可扩展**：通过继承指令模板，轻松扩展新的剧情行为

### **系统特性**

- ✅ 支持复杂的剧情演出逻辑（对话、动画、特效、音效等）
- ✅ 指令可配置跳过、等待、共存等行为属性
- ✅ 基于反射的自动序列化/反序列化
- ✅ 预制体自动匹配与资源管理
- ✅ 事件驱动的执行流程控制
- ✅ 完善的生命周期管理（Init → Execute → Interrupt → End）

## **底层：数据序列化层**

数据序列化层是整个系统的**数据基础**，负责将 JSON 格式的剧情脚本转换为可执行的指令对象。

### **核心数据结构**

系统采用**三级数据结构**：

```
FrameList (剧情脚本)
  └─ Frame[] (帧序列)
       └─ InstrParam[] (指令参数序列)
```

### **1. InstrParam - 指令参数基类**

`InstrParam` 是所有指令参数的基类，定义了指令的**元数据**和**行为属性**。

#### **核心属性**

```csharp
public class InstrParam
{
    // 指令标识
    public virtual string Name { get; protected set; }
    protected virtual string _ExecutorType { get; set; }
    
    // 行为属性
    public virtual bool IsCanCoexist { get; set; }    // 是否允许同帧共存
    public virtual bool IsRelese { get; set; }        // 执行后是否释放
    public virtual bool IsCanBeSkipped { get; set; }  // 是否可跳过
    public virtual bool IsBeWaited { get; set; }      // 是否需要等待完成
    
    // 动态获取执行器类型
    public Type ExecutorType { get; }
}
```

#### **关键机制：类型转换**

`InstrParam.Convert()` 方法实现了**多态反序列化**，这是系统的核心机制之一：

```csharp
public static InstrParam Convert(InstrParam instrParam)
{
    string jsonString = JsonSerializer.Serialize(instrParam);
    string typeName = instrParam.Name;
    
    // 通过反射查找具体类型
    Type type = Type.GetType(Namespace + typeName) 
                ?? Assembly.GetExecutingAssembly().GetType(Namespace + typeName);
    
    // 反序列化为具体类型
    return JsonSerializer.Deserialize(jsonString, type) as InstrParam;
}
```

**工作原理**：

1. 将基类对象序列化为 JSON
2. 根据 `Name` 属性查找对应的具体类型
3. 将 JSON 反序列化为具体类型对象

这使得系统可以从 JSON 中正确还原出 `TypeDialogueParam`、`IMAGParam` 等具体指令类型。

### **2. Frame - 帧**

`Frame` 代表剧情演出的一个**时间切片**，包含在同一时刻执行的多个指令。

#### **核心功能**

```csharp
public class Frame
{
    private List<InstrParam> _instructions = new List<InstrParam>();
    
    public void Add(InstrParam instruction) => _instructions.Add(instruction);
    
    // 序列化：将指令列表转换为 JSON
    public string Serialize()
    {
        var instructionJsonStrings = _instructions.Select(instr => 
            InstrParam.Serialize(instr));
        return "[" + string.Join(",", instructionJsonStrings) + "]";
    }
}
```

**设计要点**：

- 一个 Frame 可以包含多个指令，支持**并行执行**
- 通过 `IsCanCoexist` 属性控制指令是否可以在同一帧共存
- 序列化时保留每个指令的完整类型信息

```csharp
private InstrExecute GetReleasedExecutor(InstrParam param)
{
    // Step1: 查找类型匹配的已分配执行器
    KeyValuePair<InstrParam, InstrExecute>[] matchPairs = ExecutorDict
        .Where(pair => param.ExecutorType == pair.Value.GetType()).ToArray();
    
    // Step2: 筛选已释放的执行器
    List<InstrExecute> releasedExecutors = new();
    foreach (var pair in matchPairs)
    {
        if (pair.Key.IsRelese)
            releasedExecutors.Add(pair.Value);
        else if (releasedExecutors.Contains(pair.Value))
            releasedExecutors.Remove(pair.Value);  // 被占用，移除
    }
    
    // Step3: 如果没有可用执行器，创建新实例
    if (releasedExecutors.Count == 0)
    {
        GameObject _object = GameObject.Instantiate(prefabDict[param.ExecutorType]);
        InstrExecute executor = _object.GetComponent<InstrExecute>();
        releasedExecutors.Add(executor);
        Executors.Add(_object);
    }
    
    return releasedExecutors.FirstOrDefault();
}
```

**核心逻辑**：

1. `IsRelese = true` 的 `InstrParam` 加入可用列表
2. 后续 `InstrParam` 优先复用已释放的执行器（`IsRelese = true`）
3. 如果执行器被后续指令使用，则从可用列表中移除：

   1. 若 `IsRelese = true`，此 `InstrParam` 加入列表；
   2. 若 `IsRelese = false`，此 `InstrParam` 持续占用，不加入列表；
4. 没有可用执行器时才创建新实例

### **2. ObjectPool - 对象池（弃用方案）**

系统主要使用静态预分配，但也曾考虑使用对象池实现方案。

```csharp
public class ObjectPool
{
    private Dictionary<string, Queue<GameObject>> objectPool = new();
    
    public GameObject GetObject(GameObject prefab, Vector3 position = default)
    {
        // 如果池中没有可用对象，创建新对象
        if (!objectPool.ContainsKey(prefab.name) || 
            objectPool[prefab.name].Count == 0)
        {
            GameObject _object = GameObject.Instantiate(prefab);
            PushObject(_object);
        }
        
        // 从池中取出对象
        GameObject obj = objectPool[prefab.name].Dequeue();
        obj.SetActive(true);
        return obj;
    }

        objectPool[prefab.name].Enqueue(prefab);
        prefab.SetActive(false);
    }
```

**对比说明**：

- `ObjectPool`：适用于不确定数量的动态对象
- `FrameExecuteList`：适用于固定序列的剧情指令

在实际中，执行器的分配在系统启动的一刻就被决定了，在中间过程中不会有其它情况。所以在此处没有使用对象池的方式。

#### **并行执行机制**

```csharp
public IEnumerator CoSubExecute(KeyValuePair<InstrParam, InstrExecute>[] pairs)
{
    // 1. 注册事件监听
    foreach (var pair in pairs)
    {
        pair.Value.OnExecuting += OnInstrExecuting;
        pair.Value.OnCompleted += OnInstrCompleted;
    }
    
    // 2. 按序执行同类型指令
    foreach (var pair in pairs)
    {
        InstrExecute execute = pair.Value;
        InstrExecute[] exeSeq = pairs.Select(p => p.Value).ToArray();
        
        if (execute == exeSeq[0])
        {
            // 第一个指令直接执行
            execute.Init_Pack(pair.Key);
            execute.Execute_Pack();
        }
        else
        {
            // 后续指令检查是否需要等待前一个
            for (int i = 1; i < exeSeq.Length; i++)
            {
                if (execute == exeSeq[i])
                {
                    if (exeSeq[i - 1].Param.IsBeWaited && 
                        exeSeq[i - 1].ExState == ExState.Executing)
                    {
                        // 等待前一个指令完成
                        yield return new WaitUntil(() => 
                            exeSeq[i - 1].ExState == ExState.Completed);
                    }
                    
                    execute.Init_Pack(pair.Key);
                    execute.Execute_Pack();
                }
            }
        }
    }
}
```

**执行策略**：

1. **同类型指令**：按顺序执行，可通过 `IsBeWaited` 控制是否等待
2. **不同类型指令**：并行执行（通过多个协程）
3. **事件驱动**：通过 `OnCompleted` 事件统计完成数量

#### **完成检测机制**

```csharp
private void OnInstrCompleted()
{
    CompletedExes++;
    if (CompletedExes == Count)
    {
        ExState = ExState.Completed;  // 所有指令完成，帧完成
    }
}
```

**示例场景**：

```
Frame 包含 3 个指令：
- 对话指令 (IsBeWaited = false)
- 背景音乐 (IsBeWaited = false)  
- 特效指令 (IsBeWaited = true)

执行流程：
1. 对话和音乐并行开始
2. 特效等待对话完成后开始
3. 当所有 3 个指令都完成时，帧状态变为 Completed
```

```csharp
    switch (currentFrame.ExState)
    {
        case ExState.Null:
            currentFrame.Active();
            ControlFrame();  // 递归调用，继续处理
            break;
            
        case ExState.Ready:
            Execute(currentFrame);
            break;
            
        case ExState.Executing:
            Skip(currentFrame);
            break;
            
        case ExState.Completed:
            End(currentFrame);
            index++;
            
            if (index < FrameExecuteList.Count)
            {
                var nextFrame = FrameExecuteList[index];
                nextFrame.Active();
                
                if (nextFrame.ExState == ExState.Ready)
                {
                    Execute(nextFrame);  // 自动执行下一帧
                }
            }
            else
            {
                ClosePlot();
            }
            break;
    }
}
```

#### **执行方法**

```csharp
public void Execute(FrameExecute frameExecute)
{
    Dictionary<Type, KeyValuePair<InstrParam, InstrExecute>[]> exeTable 
        = frameExecute.ExeTable;
    
    // 为每种类型的指令启动一个协程
    foreach (var exes in exeTable)
    {
        StartCoroutine(frameExecute.CoSubExecute(exes.Value));
    }
}
```

**设计亮点**：

- 每种类型的指令在独立的协程中执行，实现真正的并行
- 通过状态机模式清晰管理流程
- 支持自动播放和手动推进两种模式

#### **3. ****InstrExecute****包装函数调用**

执行器类继承自 `InstrExecute` 基类，基类提供了包装函数（`_Pack` 方法）来管理生命周期和状态：

```csharp
// InstrExecute 基类中的包装函数
public abstract class InstrExecute : MonoBehaviour
{
    protected InstrParam _param;
    public InstrParam Param => _param;
    public ExState ExState = ExState.Null;
    
    // 包装函数 1: 初始化包装
    public void Init_Pack(InstrParam param)
    {
        _param = param;
        transform.SetParent(PlotPerformSys.Instance.transform);
        Init();  // 调用子类实现
        ExState = ExState.Ready;
    }
    
    // 包装函数 2: 执行包装
    public void Execute_Pack()
    {
        MarkExecuting();  // 标记为执行中，触发事件
        Execute();        // 调用子类实现
        StartCoroutine(CoExecute_Pack());  // 启动协程
    }
    
    // 包装函数 3: 协程包装
    private IEnumerator CoExecute_Pack()
    {
        yield return StartCoroutine(CoExecute());  // 调用子类实现
        MarkCompleted();  // 标记为完成，触发事件
    }
    
    // 包装函数 4: 中断包装
    public void Interrupt_Pack()
    {
        Interrupt();  // 调用子类实现
        StopAllCoroutines();
        MarkCompleted();
    }
    
    // 包装函数 5: 结束包装
    public void End_Pack()
    {
        End();  // 调用子类实现
        ExState = ExState.End;
        
        if (_param.IsRelese)
        {
            ReleaseExecutor();  // 释放执行器
        }
    }
    
    // 状态标记方法
    protected void MarkExecuting()
    {
        if (ExState == ExState.Ready)
        {
            ExState = ExState.Executing;
            OnExecuting?.Invoke();
        }
    }
    
    protected void MarkCompleted()
    {
        if (ExState == ExState.Executing)
        {
            ExState = ExState.Completed;
            OnCompleted?.Invoke();
        }
    }
    
    // 事件
    public event ExecuteHandler OnCompleted;
    public event ExecuteHandler OnExecuting;
}
```

**包装函数的作用**：

1. **统一管理状态转换**：确保状态按 `Null` → `Ready` → `Executing` → `Completed` → `End` 顺序变化
2. **触发事件通知**：在关键时刻触发 `OnExecuting` 和 `OnCompleted` 事件
3. **协程生命周期管理**：自动启动和停止协程
4. **资源释放控制**：根据 `IsRelese` 属性决定是否释放执行器
5. **解耦业务逻辑**：子类只需实现具体业务，不用关心状态管理

**包装函数调用流程图**：

**调用关系说明**：

```

    ↓ 调用
TypeDialogue (子类实现) - 具体业务逻辑
    ↓ 返回
InstrExecute (包装函数) - 后续处理
```

```csharp
using System.Collections;
using PlotPerformance.Include.Construct;
using UnityEngine;

namespace PlotPerformance.Instruction
{
    public class PlaySound : InstrExecute
    {
        private AudioSource audioSource;
        private PlaySoundParam soundParam;
        
        protected override void Init()
        {
            // 获取或添加 AudioSource 组件
            audioSource = GetComponent<AudioSource>();
            if (audioSource == null)
                audioSource = gameObject.AddComponent<AudioSource>();
            
            // 获取参数
            soundParam = Param as PlaySoundParam;
            
            // 加载音效资源
            AudioClip clip = Resources.Load<AudioClip>(soundParam.soundPath);
            if (clip != null)
            {
                audioSource.clip = clip;
                audioSource.volume = soundParam.volume;
                audioSource.loop = soundParam.loop;
                ExState = ExState.Ready;
            }
            else
            {
                Debug.LogError($"[PlaySound] 无法加载音效: {soundParam.soundPath}");
            }
        }
        
        protected override void Execute()
        {
            // 播放音效
            audioSource.Play();
        }
        
        protected override IEnumerator CoExecute()
        {
            if (!soundParam.loop)
            {
                // 等待音效播放完成
                yield return new WaitForSeconds(audioSource.clip.length);
            }
            else
            {
                // 循环播放，立即完成
                yield return null;
            }
        }
        
        protected override void Interrupt()
        {
            // 中断时停止播放
            audioSource.Stop();
        }
        
        protected override void End()
        {
            // 清理
            audioSource.Stop();
            audioSource.clip = null;
        }
    }
}
```

3. Unity GameObject 在整个剧情过程中只创建一次

- JSON 解析逻辑
